# 相机色彩矫正标定系统 (Camera Color Calibration Tool)

本项目是一个工业级的相机颜色标定与标定文件生成工具。它通过对比**标准数字模板（图像 LAB 数值）**与**相机实际采集图像（图像 RGB 数值）**，建立颜色映射模型，并生成 LUT（查找表）以校正相机拍摄的图片颜色。

> **主要应用场景**：工业印刷检测、色彩还原测试及相机 ISP 参数调优。
> **运行环境**：Windows（源码运行需 Python 3.x，打包后的 exe 无此要求）。

---

## 核心功能

### 自动特征匹配
系统采用两层匹配策略对模板图与采集图进行对齐。首先对下采样后的图像进行粗匹配，快速定位大致区域；随后回到原始分辨率，在局部区域内进行精匹配，既保证匹配速度又保证定位精度。匹配过程中的缩放比例、搜索边距比例以及最低匹配得分阈值均可通过 `config.ini` 文件灵活调整，以适应不同分辨率和拍摄条件下的图像对。

### 鲁棒的网格提取
针对色卡/马赛克网格的自动提取，系统构建了一套完整的图像处理链路：先将图像转换至 HLS 色彩空间并提取亮度分量，经 CLAHE 自适应直方图均衡增强局部对比度后，使用高斯模糊抑制噪点，再通过 Canny 边缘检测获取色块边界；随后利用形态学闭运算连接断裂边缘，基于距离变换计算各区域到边界的距离，最终通过局部峰值检测（peak local max）锁定每个色块的中心点。

考虑到实拍环境可能存在脏污、反光或噪点干扰，系统额外实现了网格校验机制：以 49 行 × 33 列的理论网格位置为基准，计算检测到的中心点相对于理论网格的中值偏移量，对整体网格进行平移修正；对于偏移后仍缺失的网格点，通过最近邻匹配在限定距离内寻找替代点，从而在不依赖人工干预的情况下获得完整且规律的网格中心点阵列。

### 颜色数据提取
在获得准确的网格中心点后，系统以每个中心点为圆心，按照配置的半径（默认为 30 像素）截取正方形区域作为该色块的采样 Patch。对每个 Patch 内的所有像素，分别计算 BGR 三个通道的算术平均值，得到该色块的平均颜色响应。所有色块的均值数据最终会经过 BGR 到 RGB 的格式转换，统一以 RGB 顺序存储，便于与标准数据对齐。

### 数据处理与导出
系统将提取到的 RGB 数据与标准 LAB 数据（来源于 `data/1_template/map.xlsx`）按行对齐合并。`map.xlsx` 中必须包含 `LAB_L`、`LAB_A`、`LAB_B` 三列标准值。合并后生成的 Excel 文件包含 `R`、`G`、`B`、`LAB_L`、`LAB_A`、`LAB_B` 等完整字段，作为后续机器学习模型训练的标准输入数据集。同时，系统会对行数不匹配的情况发出警告，并以最小有效行数进行数据合并，防止因个别色块识别失败导致整个流程中断。

### LUT 生成
基于训练完成的多层感知机（MLP）回归模型，系统会对所有可能的 RGB 组合进行预推理。对于 8bit 位深，模型会遍历 256³ 共 16,777,216 种 RGB 输入，预测其对应的 LAB 输出，再经由 LAB → sRGB 色彩空间转换，得到最终的 sRGB 校正结果。所有预计算结果以二进制格式写入查找表文件 `rgb_to_srgb.bin`（体积约 48MB）。设备端在实际运行时只需进行简单的查表操作，即可在毫秒级完成颜色校正，无需部署和运行复杂的神经网络模型。

### 效果验证
生成 LUT 后，可通过系统的功能 2 对任意图片进行批量推理验证。该模块加载已生成的 `rgb_to_srgb.bin` 标定文件，对 `data/4_test_data/input/` 目录下的所有待测图片执行逐像素查表校正，并将校正后的结果保存到 `data/4_test_data/output/` 目录。用户可通过对比校正前后的图像，直观评估标定效果，确认颜色还原是否满足预期。

## 目录结构与运行前准备

程序运行依赖严格的目录结构。无论是运行源码还是打包后的 exe，请确保**程序同级目录**下存在以下结构：

```text
Project_Root/
│
├── run.py 或 ColorCalibrationTool.exe   # [程序入口]
├── config.ini                           # [配置] 首次运行自动生成
├── logs/                                # [日志] 运行日志，自动创建
│
└── data/                                # [数据] 所有输入/输出数据目录
    ├── 1_template/                      # [输入] 标准模板数据
    │   ├── temp.bmp                     # 标准色卡模板图片
    │   └── map.xlsx                     # 标准色卡的 LAB 数值表（必须包含 LAB_L, LAB_A, LAB_B 列）
    │
    ├── 2_capture/                       # [输入] 相机采集图像
    │   └── match.bmp                    # 实拍色卡图片
    │
    ├── 3_result/                        # [输出] 程序自动生成结果
    │   ├── 1_test_temp_location.jpg     # 调试图：模板网格中心点定位结果
    │   ├── 2_test_insp_location.jpg     # 调试图：实拍图网格中心点定位结果
    │   ├── map_data_result.xlsx         # 合并后的 RGB+LAB 数据表
    │   ├── mlp_regressor_model.pkl      # 训练好的 MLP 模型
    │   ├── scaler_*.pkl                 # 数据归一化器
    │   ├── rgb_to_lab_lookup_table.bin  # RGB→LAB 查找表
    │   └── rgb_to_srgb.bin              # 最终标定文件（约 48MB，可直接复制到设备使用）
    │
    └── 4_test_data/                     # [测试] 用于验证标定效果
        ├── input/                       # 放入待测试图片（支持任意名称/格式）
        └── output/                      # 生成校正后的图片（程序自动写入）
```

### 运行前检查清单
1. 确保 `data/1_template/` 目录下同时存在模板图（`temp.bmp`）和 `map.xlsx`。
2. 确保 `data/2_capture/` 目录下存在实拍图（建议只保留一张，程序默认取目录中检索到的第一张图片）。
3. 首次运行会自动生成 `config.ini` 和 `logs/` 目录，建议根据实际图像分辨率调整 `config.ini` 中的匹配参数。

## 使用方法

双击运行程序（源码运行 `run.py`，或打包后的 `ColorCalibrationTool.exe`），控制台会显示功能菜单：

```text
-> 功能 1： 训练模型并生成标定文件 (Train & LUT)
-> 功能 2： 批量推理测试图片 (Inference)
-> 功能 3： 重新加载配置文件 (Reload Config)
-> 其他  ： 退出程序
```

- **功能 1（训练与标定）**：读取 `data/1_template/` 与 `data/2_capture/` 中的图像，依次执行模板匹配、网格提取、颜色采样、数据合并、MLP 训练与 LUT 生成，全部结果输出到 `data/3_result/`。
- **功能 2（批量推理）**：加载 `data/3_result/rgb_to_srgb.bin`，对 `data/4_test_data/input/` 中的所有图片逐像素查表校正，结果保存到 `data/4_test_data/output/`。需先运行过功能 1。
- **功能 3（重载配置）**：不退出程序的情况下重新读取 `config.ini`。

> **配置修改何时生效**：`[PATHS]` 等路径类配置通过功能 3 即可热加载；`[MATCHING]`、`[GRID]`、`[DEBUG]`、`[COLOR]` 等影响训练与 LUT 的参数，修改后需要重新运行**功能 1** 生成新的 LUT 才会在矫正效果中体现。

## 代码调用流程

以下为功能 1 从输入准备到最终输出的完整代码调用链路：

```text
输入准备
├── data/1_template/temp.bmp     (标准色卡模板图)
├── data/1_template/map.xlsx     (标准LAB数值表)
└── data/2_capture/match.bmp     (相机实拍图)
    │
    ▼
功能1: 训练与标定
├── Step1: 加载模板图 → 逆时针旋转90° → 提取49×33网格中心点
│           └── 输出: data/3_result/1_test_temp_location.jpg
├── Step2: 加载实拍图 → OpenCV模板匹配(粗匹配+精匹配) → 裁剪ROI
│           → 逆时针旋转90° → 提取网格中心点
│           └── 输出: data/3_result/2_test_insp_location.jpg
├── Step3: 按网格中心点截取Patch → 计算每个色块BGR通道均值
├── Step4: BGR → RGB格式转换
├── Step5: 与map.xlsx中的标准LAB数据按行对齐合并 → 生成Excel
│           └── 输出: data/3_result/map_data_result.xlsx
├── Step6: MLP回归模型训练 (输入: RGB → 输出: LAB)
│           └── 输出: data/3_result/mlp_regressor_model.pkl, scaler_*.pkl
└── Step7: 基于训练好的模型生成LUT查找表
            └── 输出: data/3_result/rgb_to_srgb.bin (约48MB)
    │
    ▼
功能2: 批量推理验证 (可选)
├── 读取 data/4_test_data/input/ 目录下的待测图片
├── 逐像素查LUT表进行颜色校正
└── 输出校正结果到 data/4_test_data/output/
```

## 打包指南（如何把源码变成可执行文件）

如果你想把这个项目打包成可以直接发给其他人使用的程序，不需要懂编程，项目根目录下已经准备好了"一键打包脚本" `build.bat`，双击运行即可。

### 打包前准备（只需做一次）

**第一步：确认虚拟环境 venv 存在且依赖齐全**

打包脚本强制使用项目自带虚拟环境 `venv/` 中的 Python 和 PyInstaller，以保证打包环境与开发环境一致。如果 `venv/` 不存在或依赖缺失，先在项目根目录执行：

```bat
python -m venv venv
venv\Scripts\pip.exe install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple/
```

**第二步：双击运行 build.bat**

在包含 `run.py`、`build.bat` 的项目文件夹中，直接双击 `build.bat`，打包过程开始。

**窗口中会出现以下提示（请耐心等待，不要关闭窗口）：**

- `[1/4] Checking PyInstaller...` — 脚本正在检查 venv 中的打包工具是否正常。
- `[2/4] Building executable (directory mode -D)...` — **这是最重要的一步，也是最耗时的一步**，通常需要 **1~10 分钟**。期间窗口可能看起来没有变化，这是正常的。
- `[3/4] Preparing required folders and files...` — 打包已完成，脚本正在把程序运行必需的文件夹（如 `data/1_template`）和配置文件复制到 `dist/ColorCalibrationTool/` 分发目录中，并生成 `使用说明.txt`。打包产生的 `build/` 临时目录会在这一步被自动清理。
- `[4/4] Verifying build result...` — 脚本正在检查最终生成的文件是否完整。

当窗口中出现以下字样时，表示打包成功：

```text
========================================
  Build Success!
========================================

Output directory: dist\ColorCalibrationTool\
```

> **温馨提示：为什么打包后不是一个单独的 `.exe` 文件，而是一整个文件夹？**
> 这是因为我们使用的是"目录模式"打包。如果把所有依赖库都塞进一个 `.exe` 文件里，用户每次双击运行时，电脑都需要先把压缩的文件解压到临时目录，导致启动非常缓慢。而目录模式把依赖库放在 `_internal` 文件夹中，程序可以直接读取，启动速度快得多。所以请务必以整个文件夹的形式分发。

### 分发包结构

`build.bat` 已自动把所有必需的文件复制到分发目录中，你不需要手动复制任何东西：

```text
dist/ColorCalibrationTool/      # 最终分发包文件夹
│
├── ColorCalibrationTool.exe       # [主程序] 双击即可运行
├── _internal/                     # [依赖库] 程序运行必需的库文件，不可删除
│
├── data/                          # [数据] 所有输入/输出数据目录
│   ├── 1_template/                # [必须] 标准模板数据（打包时自动拷贝）
│   ├── 2_capture/                 # [必须] 相机采集图像（需用户自行放入 match.bmp）
│   ├── 3_result/                  # [输出] 程序自动生成结果
│   └── 4_test_data/               # [测试] 验证标定效果
│
├── logs/                          # [日志] 运行日志存储
├── config.ini                     # [配置] 程序配置文件
├── README.md                      # [说明] 完整说明文档
└── 使用说明.txt                    # [说明] 快速上手指引
```

**注意： `_internal` 文件夹以及 `data` 目录下的所有文件夹都是程序正常运行所必需的。缺少任何一个，程序都无法启动。**

### 如何把程序发给其他人使用

只需要做一件事：**将整个 `dist/ColorCalibrationTool/` 文件夹拷贝给对方即可。**

对方使用 Windows 系统的电脑，无需安装 Python，无需安装任何其他软件或运行库，也无需进行任何配置。对方收到文件夹后，把实拍色卡图命名为 `match.bmp` 放入 `data/2_capture/`，然后双击 `ColorCalibrationTool.exe` 即可使用。

## 版本历史

### v1.3.0 发布版
*   **目录结构**：所有输入/输出数据目录（`1_template` ~ `4_test_data`）统一收拢到 `data/` 下，工程根目录更简洁。
*   **打包优化**：打包产物统一输出到 `dist/ColorCalibrationTool/`，并自动生成 `使用说明.txt`；`build/` 中间目录在打包完成后自动清理。
*   **打包修复**：`build.bat` 强制使用项目 `venv` 中的 PyInstaller，避免误用系统全局 Python 环境打包。

### v1.2.0 发布版
*   **新增功能**：矫正图像过曝效果控制模块。
    *   让矫正后的图像有一定对比度拉伸，同时保留白纸区域细小黑色划痕，避免因颜色矫正被淹没。

### v1.1.0 发布版
*   **新增功能**：图片色彩验证 (功能2)。
    *   生成颜色标定文件后，可直接调用功能2验证效果。
    *   需在 `data/4_test_data/input` 放入待测图片，结果输出至 `data/4_test_data/output`。
*   **优化**：提升了 1bit 的色卡标定精度。

### v1.0.1 发布版
*   **日志系统**：添加 `logs` 文件夹，存储所有运行日志。
*   **配置支持**：新增 `config.ini` 文件，支持参数调整。

### v1.0.0 发布版
*   **初始版本**：色卡标定第一版本。
